# USP_WriteCsv

## Zweck und Einsatzfälle

Schreibt einen read-only Snapshot vier typgenauer caller-lokaler Temp-Spalten als vollständig budgetiertes CSV. Kanonischer CSV-Writer aus typgenauem lokalen Zellraster.

## Voraussetzungen

Installiertes Modul mit autorisierter SAFE-Assembly tlblt_File_CsvMemory, SQL Server 2019/2022/2025 auf Windows/Linux gemäß Modulmatrix, CL150/160/170 soweit zur Engine passend, lokal oder zentral. Kein Datei-, Netzwerk- oder Encodingprovider. ResultTable >=1.0.0 in derselben Datenbank für Routing. Separator genau eine UTF-16-Codeunit, nicht NULL/leer, keine Doppelquote, CR, LF, NUL oder Surrogate. NullToken NULL deaktiviert SQL-NULL; sonst 1..128 Codeunits, ohne Separator, Doppelquote, CR, LF, NUL oder ungepaarte Surrogate. Gültige Surrogatpaare im Token sind erlaubt. Tokenvergleich exakt nach Länge und Codeunits, nicht SQL-Padding.

## Ergebnisse

Genau eine fachliche Zeile: CsvText nvarchar(max) NOT NULL, DataRows bigint NOT NULL, ColumnCount int NOT NULL. Leere Quelle ohne Header ergibt N'', 0, 0. Jeder Record einschließlich des letzten erhält CRLF oder LF gemäß @LineEnding. Header allein ist zulässig; DataRows zählt nur DATA. @ResultTable=NULL liefert den SELECT; sonst schreibt der vorhandene ResultTable-Helper in die caller-lokale #Temp und es gibt keinen fachlichen SELECT. @KeepData=0 ersetzt Ergebnisdaten, 1 hängt kompatibel an, NULL entspricht 0. RETURN 0 bei Erfolg, keine OUTPUT-Parameter. @Hilfe=1 liefert zuerst die bestehende zwölfspaltige Hilfe und dann genau eine Zeile SkillFormatVersion varchar(16), SchemaName sysname, ObjectName sysname, SkillMarkdown nvarchar(max), ohne Fachausführung.

## Aufrufbeispiele

```sql
CREATE TABLE #CsvCells(RowKind varchar(6),RowOrdinal bigint,ColumnOrdinal int,[Value] nvarchar(max));
INSERT #CsvCells VALUES('DATA',1,1,N'a,b'),('DATA',1,2,N'x');
EXEC toolbelt_file.USP_WriteCsv @CellsTable=N'#CsvCells',@LineEnding='LF';
-- CsvText: Doppelquote a,b Doppelquote ,x gefolgt von LF; DataRows=1, ColumnCount=2.
DROP TABLE #CsvCells;
EXEC toolbelt_file.USP_WriteCsv @Hilfe=1;
```

## Rechte

Vorhandenes EXECUTE auf dieser USP sowie beiden internen Skalaren SVF_InternalMeasureCsvCell und SVF_InternalQuoteCsvCell. Bei Routing zusätzlich vorhandenes EXECUTE auf toolbelt_core.USP_PrepareResultTable und dessen vorhandene Abhängigkeitsrechte. Caller muss eigene lokale Temps sehen/lesen bzw. ändern können. Writer prüft tempdb.sys.columns, Routing sys.parameters des Helpers; notwendige Metadatensichtbarkeit muss bestehen. Keine neue Rechtevergabe oder Identitätsumschaltung durch die Prozedur. Zentraler Dreiteilname allein ersetzt keine Cross-DB-Rechte.

## Ressourcenbedarf

Feste Obergrenzen: 100000 DATA-Records, 1024 Spalten, 1000000 Zellen einschließlich HEADER, 16777216 UTF-16-Bytes. Positive Aufrufbudgets dürfen diese Grenzen nur absenken. Das ist keine Heap-, Memory-Grant-, CPU-, Wallclock- oder Produktionskapazitätsgarantie. Writer prüft zuerst höchstens MaxCells+1 Quellzeilen und DATALENGTH-Summe, DATA-Zeilen/MaxColumn vor LOB-Snapshot, danach nochmals Snapshotgrenzen. @MaxValueBytes ist die Summe aller nicht-NULL Value-DATALENGTHs, keine separate zusätzliche Einzelzellquote. Alle Zellen werden vollständig gemessen, danach Separatoren und alle Recordabschlüsse eingerechnet. Erst nach globalem MaxOutputBytes-PASS werden Fragmente und STRING_AGG-Ausgabe allokiert, dann einzelne und gesamte Bytelängen abgeglichen. Mehrere vollständige private Temp-/LOB-Darstellungen möglich; kein Streaming.

## Nebenwirkungen

Writer liest die Quelle mit TABLOCK,HOLDLOCK innerhalb eigener Transaktion oder Caller-Savepoint und schreibt nicht in die Quelle. Sperren können bis zum Ende einer bestehenden Callertransaktion fortbestehen. Private #tbx_CsvWrite_* Temps sind reserviert; vorhandene gleichnamige Caller-Temps und #tbx_-Argumentnamen werden vor separater Batchkompilierung abgewiesen. Bei eigenem Transaktionsscope Commit/Rollback nur der eigenen Transaktion; bei bestehender Callertransaktion Savepoint und nur bei XACT_STATE()=1 Rollback dorthin. Kein vollständiges Commit/Rollback der Callertransaktion. Ein technischer Fehler kann sie uncommittable lassen. Savepoints in nicht unterstützten Transaktionen können scheitern. Rollbackfehler werden nicht gesondert abgefangen und können den ursprünglichen Fehler überlagern. SET NOCOUNT ON, optionale abstrakte Diagnose und private temporäre Ergebnisse; keine Dateien, Netzwerkzugriffe, Serverkonfiguration oder persistenten Fachänderungen. Nur ausdrücklich angegebene ResultTable darf ihre Form/Daten gemäß Helpervertrag ändern. Hilfe kehrt davor zurück.
